- **CR-01 (script):** `Get-FullPath` keeps `\\?\`, `\\.\` and UNC prefixes, so `-Out \\?\C:\{repo}\out` passes `Test-SameOrUnder`, vdiff writes into the repository, and the script only notices afterwards (reason `repo-changed`). A junction whose target is a volume GUID path is also a hole: PowerShell reports its `Target` as `Volume{...}\...` without prefix, the resolver combines that with the link's parent directory and returns a path that matches nothing (fail open).
- **WR-01 (script):** the script never writes the five output files (the vdiff child does, fixed in plan 01-13). It does write one file itself, the `-LogPath` log, with a whole-file write that follows a pre-planted hard link or file symbolic link into the repository.
- **WR-02 (script):** `-LogPath` is checked before the vdiff run (up to 25 minutes) and written after it with no second check.

Purpose: roadmap criterion 2 and decision D-02 for the trial run on the private clone (TRC-03; threats T-01-26 and T-01-37 are hardened further, cited in prose). The rules of the CLI and the script must agree.

Decisions recorded in this plan (Claude's discretion; K-numbers continue plan 01-13's list):

- **S-1, the same accept-list.** `Test-NonDriveRoot` returns true on Windows when the full path text does not start with an ASCII letter, a colon and a backslash (a pattern match on the text, never on `[IO.Path]::GetPathRoot`, which returns an empty root for a volume GUID path on Windows PowerShell 5.1 and a root without its trailing separator for the device form; both verified at planning time). It is false on other platforms. It is applied inside `Resolve-FinalPathStep` (so every path and every link target the resolver sees, including the protected directories) and explicitly to `$outFull` and `$logFull` so the reasons are `out-not-outside` and `bad-arguments` rather than `script-error`.
- **S-2, a volume GUID link target throws.** In `Resolve-FinalPathStep`, after the existing strip of a leading `\??\`, a target that begins with `Volume{` (case-insensitive) throws, the same fail-closed rule as the C# resolver (K-6 of plan 01-13). PowerShell reports such targets without the prefix on both hosts (verified at planning time), so the check is on that spelling.
- **S-3, the raw `-Repo` spelling is protected only when it is a drive-letter path.** `$protected` gets `$repoFull` only when `Test-NonDriveRoot` is false for it. The three git-reported roots already protect the repository: git reports a drive-letter root for a repository addressed through the extended or the device spelling (verified at planning time), and for a UNC-hosted repository git refuses by default and otherwise reports a non-drive root, which the resolver refuses (`script-error`, fail closed), as the CLI does (K-3 of plan 01-13: UNC-hosted repositories are refused on Windows).
- **S-4, the log is written by deleting the entry, then creating it new.** `Write-LogFile` looks the entry up with `Get-Item -LiteralPath -Force`; a directory, a symbolic link or a junction at that name means no log is written (`CreateNew` would follow a dangling link and create its target); a plain file or a `HardLink` entry is removed with `[IO.File]::Delete`, which removes only the directory entry; then the file is opened with `FileMode.CreateNew` and written. `File.Move` with overwrite does not exist in Windows PowerShell 5.1, so the C# temp-name pattern is not available; both mechanisms were exercised on both hosts at planning time for a hard link entry.
- **S-5, a second check before the log write, with a silent skip.** The log is diagnostic. After the vdiff run the script repeats the namespace test and the containment loop for `$logFull` and calls `Write-LogFile` only when nothing matches; the block stays inside the existing swallow-all try/catch, so an unresolvable or unsafe path skips the log and no reason changes (the six-line vocabulary has no fitting reason, and the result of the run must not depend on a diagnostic file).
- **S-6, no script-side change for the five output files.** The script passes `--out $outFull` to vdiff; plan 01-13's temp-name write and second check cover them.
