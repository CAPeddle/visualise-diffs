Decisions recorded in this plan (Claude's discretion; `01-CONTEXT.md` fixes only D-02, D-03 and D-09; L-numbers are new, H-numbers are plan 01-16's):

- **L-1, Add-Type, a named decision.** Plans 01-12 and 01-15 (R-1) declined a final-path route because Windows PowerShell 5.1 "cannot call it without compiling code", and AR-04 repeats that reason. Planning-time probe (scratch directories only): `Add-Type -MemberDefinition` with the two declarations below compiles in about 220 ms on 5.1 and 440 ms on 7, and the compiled calls behave identically on both hosts (final path of a directory opened through a junction: the target's `\\?\C:\...` form with its real casing; a held directory and its parent refuse a rename). This plan therefore compiles code in the script for the swap window only. The consequence for AR-04 is recorded, not edited: its technical rationale no longer holds for the script, so the row now rests on the product owner's sign-off (UAT test 6). The measured alternative, an open file in the directory (it also freezes the chain), was not chosen because it needs a double check and leaves a file in the log's directory; the product owner's wording allowed either, and only the handle route lets the truth say "closed".
- **L-2, lazy compile, silent skip.** The type is compiled only when `-LogPath` is given on Windows, from a fixed single-quoted text. Any failure to compile or to hold (for example Constrained Language Mode) skips the log silently and the run goes on, as the post-run block already does for an unresolvable path; only a protected verdict changes the outcome.
- **L-3, hold before the run, write after it.** The log directory is opened and judged after all pre-run checks and before the repository snapshot, and held until the log is written (a `finally` closes it), so the whole check-to-write interval is covered and a test can stage a swap during the run. Cost: a missing log directory chain is created before the run instead of after it; a run that ends early leaves that empty chain. The post-run by-name containment re-check is kept only where no handle is held (Linux and macOS): with a handle the final path judged before the run is the decisive fact, and a by-name re-check after a retarget would suppress a log that is safely written.
- **L-4, `-Out` through the environment.** The CLI cannot know the vdiff root and D-03 fixes its arguments, so the script passes the root in `VDIFF_PROTECTED_DIRS` (a list separated by the platform's path separator, at most 8 absolute entries), as the CLI already takes `VDIFF_CPP_TS` and the sidecar limits from the environment. The variable only adds protected directories: an unset or hostile environment cannot weaken the guard (T-01-58). The CLI applies it at both text checks and in the held directory's judgement (plan 01-16 left the extension point: the function passed to `HeldDirectory.Create`).
- **L-5, test infrastructure.** A fake sidecar mode `ok-empty-after-delay` (delay from `FAKE_SIDECAR_DELAY_MS`) keeps a real vdiff run busy for seconds and then lets it succeed (planning-time probe: the built `vdiff.dll`, run once against a synthetic two-commit repository with `FAKE_SIDECAR_MODE` set to `ok-empty` and `VDIFF_CPP_TS` naming the fake, exits 0, prints `wrote 5 files` and writes the five files, so a fake that replies an empty file list is a successful run and the new mode only adds the delay); the stand-in vdiff root is a scratch directory holding a copy of the script, so no link ever points at this checkout; staged tests wait for the fake's pid file, which is written after the script's holds.
- **L-6, scope guard.** As H-6: the judgement compares what the operating system reports for the open handle with the protected roots as `Resolve-FinalPath` renders them; for a spelling the text walk does not fold the two can differ.
