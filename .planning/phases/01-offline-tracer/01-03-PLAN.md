<objective>
The end-to-end tracer: one `vdiff` run reads two commits from git objects (plan 01-02), extracts C++ types and members through the sidecar (plan 01-01), diffs them, and writes the five output files under `--out`, leaving the analysed repository untouched.

Purpose: this is the phase's thin, production-quality slice through every layer. It proves the architecture end to end (TRC-01, TRC-02) and puts the sidecar ADR-001 chose to real use (SPK-02) before any hardening is spent. Plans 01-04 to 01-09 then harden individual layers in parallel against the names and shapes fixed here.

Output: model types and builder, differ, three writers, CLI, the `vdiff` executable project, the end-to-end test. Task 2 is the blocking package-legitimacy checkpoint for the npm tools plan 01-09 installs; its answer is recorded in this plan's SUMMARY.

Size note: task 1 lists 13 files because a tracer is one file per layer (model, build, diff, three writers, CLI options, CLI app, executable project, test); every file is kept minimal and the hardening is owned by later plans.

MODEL (`Model.ModelTypes`): records serialised with snake_case names (property order is declaration order). `ModelFile`: `schema` "vdiff-model/v0-tracer", `commit`, `extraction` {`extractor` "cpp-ts", `mode` "syntax-only", `tree_sitter`, `tree_sitter_cpp`, `macros_blanked`}, `files` [{`path`, `error_nodes`}], `unmodelled` [{`path`, `reason`}], `types`. `TypeModel`: `id`, `fqn`, `kind`, `name`, `scope`, `file`, `bases`, `span`, `members`. `MemberModel`: `key`, `name`, `kind`, `access`, `signature`, `span`. `SourceSpan`: start_byte, end_byte, start_line, end_line. `DiffFile`: `schema` "vdiff-diff/v0-tracer", `base`, `head`, `summary` {`types` {added, removed, modified, unchanged}, `members` {added, removed, modified}}, `warnings`, `types` (only changed types). `TypeDiff`: `id`, `fqn`, `kind`, `state`, `base_file`, `head_file`, `bases` {added, removed}, `members`. `MemberDiff`: `key`, `name`, `state`, `access_before`, `access_after`, `signature_before`, `signature_after` (nulls omitted). States added, removed, modified, unchanged.
`Model.ModelBuilder.Build(commit, response, unmodelled, macros)`: `fqn` is scope + `::` + name (name alone when scope is empty); `id` is kind + a space + fqn; types sorted by id and members by key, ordinal; duplicate ids (type or member key) are made unique by suffixing `#2`, `#3` in source order so a run never crashes on repeated definitions.
DIFF (`Diff.ModelDiffer.Diff(baseModel, headModel)`, D-07): match types by id; only in head is added with all members added; only in base is removed with all members removed; in both, compare `bases` as sets and members by key (only in head added, only in base removed, in both with a different `access` or `signature` modified); a type with any change is modified, else unchanged and counted but not listed; warnings state per side the number of files with parse errors and the number not modelled; everything ordinal-sorted.
OUTPUT (D-08, five files in `--out`, model JSON labelled `vdiff-model/v0-tracer`): `OutputWriter` holds the canonical JSON serialiser (indented, `NewLine` set to LF, snake_case, nulls omitted, trailing LF) and `WriteAll(outDir, baseModel, headModel, diff, mermaid, html)`, which writes the five fixed file names as UTF-8 without BOM using LF; repository paths are never used as file names (T-01-28). `MermaidWriter.Render(DiffFile)` emits `classDiagram`, then per changed type ordered by id `class <id>["<fqn>"]:::<state> {` with one line per changed member (visibility character: + public, # protected, - private; the signature; a space; `[<state>]`), then one `classDef` line each for added, removed and modified using the colours in the S1 sample; the class id is the fqn with every character outside letters, digits and underscore replaced by an underscore, made unique; escape `{`, `}` and `~` in member text and `"` in labels with look-alike characters (U+2774, U+2775, U+223C, U+2033). `HtmlWriter.Render(DiffFile, mermaid)` returns one self-contained page (charset meta, inline CSS, a summary line, the warnings, a table of changed types and members with their states, the Mermaid text in an escaped pre block); every repository-derived value passes through `WebUtility.HtmlEncode`; no script element, no external URL, no remote font or image (T-01-06).
CLI (D-03): `Cli.CliOptions.Parse(args)`: required `--repo`, `--base`, `--head`, `--out`, each once with a value; repeatable `--blank` (an ASCII identifier, at most 256 names) and `--include` (non-empty, no NUL, at most 512 characters, at most 64 globs); `--help` prints usage to stdout and exits 0; any other argument is an error; `--base` and `--head` must be 7 to 64 hexadecimal characters (T-01-01). `Cli.CliApp.Run(args, stdout, stderr)` returns 0 or 1 (R27 contract) and prints `vdiff: <message>` to stderr on failure, never file content. Flow: parse; require `--repo` to be an existing directory that git accepts; resolve both commits; compute the full `--out` path and refuse it when it lies inside the repository work tree or git directory (via `ToplevelOrGitDir`) or exists as a file, comparing on directory boundaries with OrdinalIgnoreCase on Windows and Ordinal elsewhere (T-01-28); `ListChanged`; keep in-scope C++ entries through `ScopeFilter` (D-10: only changed files are extracted, per side); for each side read that side's blobs and call the sidecar once, passing the `--blank` names (D-05); build both models; diff; render; create `--out` only now and write all five files, so a failure before the write leaves `--out` absent or untouched. `Vdiff.Cli` is an Exe with AssemblyName `vdiff` referencing `Vdiff.Core`; add it to `vdiff.sln`; `Program.Main` only calls `CliApp.Run` with the console writers.
