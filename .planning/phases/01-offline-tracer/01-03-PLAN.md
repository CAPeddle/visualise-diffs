  <files>extractors/cpp-ts/src/extract.rs, tests/Vdiff.Tests/Extraction/RichFixtureEndToEndTests.cs</files>
  <behavior>
    - `enum Color { Red, Green }` and `enum class E : unsigned char { X }` give a type of kind `enum` with `bases` holding the underlying type text (empty when none) and one member per enumerator (`kind` enumerator, `access` none, `key` the name, `signature` the enumerator text such as `B = 2`).
    - A class, struct or enum declared inside a class or struct is its own type whose `scope` includes the enclosing type (`shop::Box` as scope of `Mode`); a `field_declaration` that declares only a type yields no member; one that also declares a variable yields that variable as a field.
    - `using Item = std::pair<int, int>;` and `typedef int Handle;` inside a type give members of kind `alias`.
    - A `template_declaration` around a class or struct still yields the type under its plain name (template parameters are not tracked; a specialisation keeps its template arguments in the name, `Spec<int>`); a member template yields one member whose signature includes the template header.
    - Names: destructor `~Box`, operator `operator==`, call operator `operator()`, stream operator `operator<<`, and a conversion operator recomposed as `operator bool` even though the grammar places `operator` in the type position and `bool` in the declarator; constructors by their name; an `explicit` or `override` or `= 0` specifier stays in `signature`, not in `key`.
    - A function-pointer field such as `int (*cb)(int);` is kind field; `int n_, m_;` gives two fields; a `const` and a non-const overload have different keys; friend, using and static_assert children yield nothing.
    - An in-class function body and a constructor initializer list are excluded from `signature`.
    - Unions are not extracted (kind is limited to class, struct, enum).
    - Output order is deterministic: types in source order, parents before nested types.
  </behavior>

  <files>extractors/cpp-ts/src/blank.rs, extractors/cpp-ts/src/main.rs, tests/Vdiff.Tests/Extraction/BlankingEndToEndTests.cs</files>
  <behavior>
    - Length preserved: output length equals input length for every input; only bytes inside a matched macro change, and they become spaces.
    - Whole word only: `EXPORT_API_X`, `MY_EXPORT_API` and `EXPORT_APIS` are untouched when `EXPORT_API` is blanked; a name that is a prefix of another (`EXPORT` and `EXPORT_API`) blanks each correctly; matching is case-sensitive.
    - Lines whose first non-blank byte is `#` are untouched, including an indented `  #define`; a macro at the very start or end of the file is blanked; adjacent and repeated macros on one line are all blanked.
    - Multi-byte UTF-8 next to a macro is never altered; a file with a byte-order mark keeps it, and spans of types after it are offset by exactly 3 bytes.
    - End-to-end (CLI): a synthetic head commit with `class EXPORT_API Foo : public Base { ... }` run without `--blank` yields no type with id `class Foo`; with `--blank EXPORT_API` it yields `class Foo` with base `Base` and its members; repeating `--blank` for two macros records `macros_blanked` sorted and distinct in `head.model.json` and `base.model.json`; a member declared after a macro on the same line has `start_byte` equal to its true UTF-8 offset in the committed file bytes.
