Close the three findings of the gap-closure re-review (`01-REVIEW.md`: CR-01, WR-01, WR-02) on the CLI side. They were reproduced in `01-VERIFICATION.md` (Behavioral Spot-Checks, the three FAIL rows) and recorded as residuals pending an owner decision; the owner chose option (b) of the human item in `01-UAT.md` test 1: a hardening plan instead of accepting them. Plan 01-14 closes the same findings in `scripts/trace-run.ps1`.

- **CR-01:** `--out` spelled `\\?\C:\{repo}\out-ext` or `\\localhost\C$\{repo}\out-unc` passes `CliApp.RefuseUnsafeOut` (the lexical and the link-resolved test both compare spellings, and these spellings are neither links nor equal text) and the five files land inside the repository, exit 0.
- **WR-01:** a hard link or file symbolic link planted at one of the five output names inside a real `--out` makes `OutputWriter.WriteText` write through it into the repository.
- **WR-02:** containment is checked once, before `TracerPipeline.Run` (up to the 20-minute budget), and not again before the write. This is threat T-01-40, accepted in plan 01-12; this plan mitigates it and tracks the mitigation as T-01-43 (the threat model explains why it gets a new row).

Purpose: roadmap criterion 2 (a run never changes the repository it reads; everything the run writes lands in `--out`), decisions D-02 and D-03, threat T-01-28. In the target product `--out` is chosen by pipeline code, so the forms are unlikely, but the class is removed for the price of one accept-list, one write pattern and one repeated call.

Decisions recorded in this plan (Claude's discretion; `01-CONTEXT.md` fixes only D-02, D-03, D-08 and D-09 for this area):

- **K-1, one rule for both sides.** On Windows the full path (`Path.GetFullPath`) must begin with an ASCII letter, a colon and a backslash, or it is refused. This is an accept-list on the full path text, not a test on `Path.GetPathRoot`: a planning-time probe showed Windows PowerShell 5.1 returns an empty root for a volume GUID path and a root without its trailing separator for the device form, so a "root starts with two backslashes" rule would disagree between hosts. The rule lives in `FinalPath` only. `CliApp.IsSameOrUnder` stays lexical (`CliOptionsTests` calls it on non-existent paths). Plan 01-14 mirrors the rule in the script.
- **K-2, a dedicated fixed message.** The refusal is `FinalPath.UnsupportedRootMessage`, printed as `vdiff: ` plus the message and a line feed. It does not reuse `--out must not lie inside the analysed repository`: for a UNC share that is not inside the repository that text would be false, and the tool cannot tell. The containment text stays byte-identical for the cases that really are containment (the first comparison and the resolved comparison). This deliberately departs from the pattern map's suggestion to reuse one text; no existing test passes a non-drive path.
- **K-3, UNC-hosted repositories are refused.** The three protected roots go through the same resolver, so a repository whose git-reported root is in a non-drive namespace is refused on Windows. Planning-time probe on the dev host: git reports a drive-letter root for a repository addressed through the extended or the device spelling (so the mirror direction is already caught by the lexical test and gets a guard test), and for a loopback UNC repository git refuses by default ("dubious ownership") and, when told to trust it, reports a `//host/share/...` form. A network share must be reached through a mapped drive letter; that alias form stays inside the T-01-39 bound.
- **K-4, temp name plus move for the writes** (the reviewer's fix route and the pattern map): each output is written to `{name}.tmp-{random}` created with `FileMode.CreateNew` in `--out`, then moved onto the final name with overwrite. A move replaces the directory entry, so a planted hard link or file symbolic link is replaced and the file it pointed to is not touched. A process killed between the create and the move can leave one `*.tmp-*` file in `--out`, never in the repository; accepted.
- **K-5, the re-check and its seam.** `RefuseUnsafeOut` runs again immediately before `OutputWriter.WriteAll`. The WR-02 test needs a swap between the two checks, so `CliApp.Run` gets an internal overload taking an `Action?` that runs after the in-memory work; the public three-argument `Run` delegates to it. This needs `InternalsVisibleTo` for `Vdiff.Tests` in `src/Vdiff.Core/Vdiff.Core.csproj`, which does not exist yet.
- **K-6, a volume GUID link target is refused** with the same fixed message, in both implementations, so the C# result does not depend on how a given runtime reports such a target (the planning probe showed the runtime resolving it correctly while PowerShell reports it as a prefix-less relative-looking string).
- **K-7, T-01-39 is re-worded at the guard.** The three places (`CliApp.RefuseUnsafeOut`, `FinalPath.Resolve`, the `trace-run.ps1` header) must name exactly what remains unresolved after plans 01-13 and 01-14: subst and mapped drive letters, DOS 8.3 short names, and the open review findings IN-03 (link targets written without a drive letter) and IN-04 (case-insensitive file systems other than Windows compared case-sensitively). Other namespaces and volume GUID link targets are refused, not resolved (T-01-41). Each of the three keeps at least one `T-01-39` citation (plan 01-12's acceptance greps count them).

Review items IN-01 (IOException text with a path), IN-02, IN-03, IN-04, WR-03, WR-04, IN-05 and IN-06 stay open and outside this plan. File links and hard links live in a sandbox's output directory (never in the checkout) and are plain entries removed by name.
