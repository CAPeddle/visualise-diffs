<objective>
Harden the output layer: a Mermaid summary that stays valid for real C++ signatures and cannot be altered by repository text, a self-contained HTML report that encodes everything it shows, byte-identical deterministic output, and a real local Mermaid syntax check.

Purpose: ROADMAP criterion 3 needs a Mermaid `classDiagram` with a `classDef` per state and trailing member tags that passes a syntax check, and an HTML page that opens offline. Real C++ signatures contain `<`, `*`, `&`, `{`, `~`; the check measured during planning showed that only braces break Mermaid's parser, and a trailing `*` or `$` would be read as a member classifier, so the writer escapes and orders its text (TRC-02, D-08, T-01-06, T-01-20).

Output: hardened `MermaidWriter`, `HtmlWriter`, `CanonicalJson`, `OutputWriter`; four test classes plus a lint helper; `tools/mermaid-check` (script, `package.json`, committed lockfile).

  <files>src/Vdiff.Core/Output/MermaidWriter.cs, tests/Vdiff.Tests/Output/MermaidLint.cs, tests/Vdiff.Tests/Output/MermaidWriterTests.cs</files>
  <behavior>
    - Output starts with `classDiagram`, uses LF, ends with exactly one LF, orders class blocks by id, then inheritance edges sorted, then exactly three `classDef` lines (added, removed, modified) with the S1 colours; unchanged types are never drawn.
    - Class id: the fully qualified name with every character outside letters, digits and underscore replaced by an underscore, prefixed with `T` when it starts with a digit, made unique with a `_2`, `_3` suffix in canonical order; label is `["<escaped fqn>"]`; every class line carries `:::<state>`.
    - A changed type with no changed members (for example a base-list change only) is a single class line without a body; otherwise members appear one per line in key order.
    - Member line: visibility character (`+` public, `#` protected, `-` private, `+` when access is none), then the signature (`signature_after`; for a removed member `signature_before`), a space and `[state]`. The signature falls back to the member name when empty.
    - Escape table applied to member text and labels: `{` to U+2774, `}` to U+2775, `~` to U+223C, `"` to U+2033, any control character or newline to a single space. The member text never ends with `*` or `$` because the tag is last.
    - Edges: for each displayed type and each base entry, strip template arguments (balanced angle brackets) and a leading `::`, resolve by exact fully qualified name among displayed types, else by a unique displayed type whose name ends with `::` plus the base; emit `<baseId> <|-- <derivedId>` once per pair; unresolved bases produce no edge and no node.
    - Table-driven cases: `operator<<`, `std::map<int, std::vector<char*>>`, `T&&`, `~Foo()`, `int x{5}`, a function-pointer field, a quote and a backtick, non-ASCII text, and an injection attempt `a() } class Evil:::added { +b()` after which the number of `class ` lines still equals the number of displayed types.
    - `MermaidLint.Check` returns an empty problem list for every writer output in these tests and a non-empty list for hand-made broken input (missing `classDiagram`, unbalanced braces, a class without `:::state`, a class whose state has no `classDef`, a member line without a trailing state tag, a brace inside a member line).
  </behavior>
