<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| CLI arguments to git | commit ids and paths come from the user and reach `git` as argument values |
| analysed repository to vdiff | tree contents, paths and blobs are untrusted input, possibly hostile |
| vdiff to sidecar process | file bytes cross a process boundary; the child can hang, flood or crash |
| ambient environment to child processes | variables such as GIT_DIR can redirect git to another repository |
| repository-controlled git configuration | `core.fsmonitor` in the analysed repository can run a command or start a daemon during a "read" |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-01 | Tampering | commit-id handling in `GitObjectReader` | high | mitigate | Hex-only 7 to 64 character ids validated before any process starts, `rev-parse --verify --end-of-options`, ids re-validated before use, ArgumentList only, no shell; plan 01-04 adds hostile-argument tests |
| T-01-02 | Tampering | any git call against the analysed repository | high | mitigate | Only `rev-parse`, `diff-tree`, `cat-file`; global `--no-optional-locks`; ambient GIT_DIR family removed; RepoSnapshot proves it in plans 01-03 and 01-04 |
| T-01-30 | Elevation of privilege | a repository-controlled `core.fsmonitor` run by `diff-tree` or `status`, or the fsmonitor daemon started in the analysed repository | high | mitigate | `-c core.fsmonitor=false` on every git call through the single `GitCommand.Prefix` (also used by RepoSnapshot and the trial script); unit tests on the argument builder; plan 01-04 adds a marker-hook repository and a Windows `core.fsmonitor=true` scenario to the matrix |
| T-01-31 | Spoofing | a branch or tag named like a commit abbreviation redirecting the analysis to another commit | medium | mitigate | After `rev-parse`, the resolved full id must start with the input; hostile test in plan 01-04 |
| T-01-05 | Denial of service | sidecar subprocess and any child | high | mitigate | BoundedProcess: timeout, stdout cap, stderr cap with concurrent drain, kill of the process tree; plan 01-05 proves it with a fake sidecar |
