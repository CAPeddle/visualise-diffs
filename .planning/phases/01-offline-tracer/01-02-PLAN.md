  <behavior>
    - `ResolveCommit` accepts 7 to 64 hexadecimal characters (either case) and returns the full id; `HEAD`, branch names, `--output=x`, 6 characters, 65 characters, whitespace and an empty string are rejected as `VdiffException` before any process starts; a valid-looking unknown id is rejected after `rev-parse`.
    - `ListChanged(base, head)` on a synthetic repository returns added, modified and deleted regular files with both blob ids and decoded paths, in a stable order; a mode-only change, a submodule entry and a symlink are not returned; a path that is not valid UTF-8 comes back unmodelled with reason `non-utf8-path`, shown on the pure parser `GitObjectReader.ParseDiffTree(byte[] raw)` fed hand-made bytes (such a path cannot be created through git on Windows).
    - `ReadBlobs` returns exact bytes; a blob over the cap is unmodelled with reason `too-large` and is never read into memory; a blob whose loose object file was deleted in the sandbox is unmodelled with reason `object-missing`.
    - The child environment drops GIT_DIR, GIT_WORK_TREE, GIT_INDEX_FILE, GIT_COMMON_DIR, GIT_NAMESPACE and GIT_EXTERNAL_DIFF and sets GIT_OPTIONAL_LOCKS=0, GIT_TERMINAL_PROMPT=0 and GIT_NO_LAZY_FETCH=1, shown by a test on the pure environment-building function.
    - `ToplevelOrGitDir` returns the work-tree root for a normal repository and for a subdirectory, and the git directory for a bare repository.
    - `ScopeFilter`: extensions .h .hpp .hh .hxx .cpp .cc .cxx are in scope case-insensitively; `.c`, `.cs`, `.txt` and no extension are not; with globs a path must match at least one.
  </behavior>
  <action>
`Git.GitObjectReader(repoPath)` (D-02). Every call is `git --no-optional-locks -C <repo> ...` through `BoundedProcess`. `ResolveCommit(hex)` validates first, then runs `rev-parse --verify --quiet --end-of-options <hex>^{commit}` (T-01-01). `ListChanged(baseOid, headOid)` runs `diff-tree -r -z --raw --no-renames --no-abbrev <base> <head>` and hands the bytes to the public static pure function `ParseDiffTree(byte[] raw)`, which parses the NUL-separated records (`:mode mode oid oid status`, NUL, path, NUL), keeping only entries whose side is a regular file (mode 100644 or 100755) and dropping entries whose two blob ids are equal (a mode-only change; D-10 skips files whose base and head blobs are identical). D-02 names `git diff --name-status`; this uses the plumbing form of the same comparison because it never runs external diff drivers or textconv, returns both blob ids in one call and is NUL-delimited; the intent of D-02, reading only git objects and writing nothing, is unchanged. `ReadBlobs(oids, maxBlobBytes)` first runs `cat-file --batch-check` to learn sizes and types, then `cat-file --batch` for the blobs within the cap (4 MiB each; T-01-07); ids sent to git stdin are re-validated as 40 or 64 hex characters. The environment rules (T-01-02, T-01-08) include GIT_NO_LAZY_FETCH so a partial clone fails offline instead of fetching and writing into `.git`. `ToplevelOrGitDir()` supports the `--out` containment check in plan 01-03. `Scope.ScopeFilter(includeGlobs)`: `IsInScope(path)` per D-10, glob matching through `Microsoft.Extensions.FileSystemGlobbing` with ordinal comparison; plan 01-07 hardens it. All repositories in `GitObjectReaderTests` are synthetic (D-09); a missing object is made by deleting a loose object file inside the sandbox.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| CLI arguments to git | commit ids and paths come from the user and reach `git` as argument values |
| analysed repository to vdiff | tree contents, paths and blobs are untrusted input, possibly hostile |
| vdiff to sidecar process | file bytes cross a process boundary; the child can hang, flood or crash |
| ambient environment to child processes | variables such as GIT_DIR can redirect git to another repository |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-01 | Tampering | commit-id handling in `GitObjectReader` | high | mitigate | Hex-only 7 to 64 character ids validated before any process starts, `rev-parse --verify --end-of-options`, ids re-validated before use, ArgumentList only, no shell; plan 01-04 adds hostile-argument tests |
| T-01-02 | Tampering | any git call against the analysed repository | high | mitigate | Only `rev-parse`, `diff-tree`, `cat-file`; global `--no-optional-locks`; ambient GIT_DIR family removed; RepoSnapshot proves it in plans 01-03 and 01-04 |
| T-01-05 | Denial of service | sidecar subprocess and any child | high | mitigate | BoundedProcess: timeout, stdout cap, stderr cap with concurrent drain, kill of the process tree; plan 01-05 proves it with a fake sidecar |
| T-01-07 | Denial of service | very large blobs | medium | mitigate | 4 MiB per-blob cap through `cat-file --batch-check` before reading; oversized files are unmodelled, never buffered |
| T-01-08 | Spoofing | inherited git environment, lazy fetch in partial clones | medium | mitigate | GIT_DIR family removed; GIT_NO_LAZY_FETCH=1 so a missing object is unmodelled instead of fetched (no network, no write into `.git`) |
| T-01-09 | Elevation of privilege | sidecar located through env var VDIFF_CPP_TS | low | accept | Set by the invoking user on their own machine; same trust as PATH; named in the locator error text |
| T-01-SC | Tampering | NuGet packages (FileSystemGlobbing, xunit stack) | low | accept | NuGet is outside the cargo and npm legitimacy gate; the packages are Microsoft and xunit.net releases at the versions the SDK template emits |
</threat_model>
