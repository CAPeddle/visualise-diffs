  <behavior>
    - A member with the same key and a different `signature` is `modified` with `signature_before` and `signature_after`; a different `access` only is `modified` with `access_before` and `access_after`; both changed lists both pairs.
    - `f(int)` and `f(long)` are different members; `f() const` and `f()` are different members; a changed parameter list gives the old member removed and the new one added (parameter renames stay removed plus added until Phase 5, documented in the summary).
    - A changed base list gives a modified type with `bases.added` and `bases.removed` sorted, members untouched; an enum's underlying type (held in `bases`) behaves the same.
    - A type unchanged in content is excluded from `types` but counted in `summary.types.unchanged`; an unchanged member is not listed; summary counts equal the listed entries.
    - Same fully qualified name with a different kind (class to struct) is one removed type and one added type (D-07).
    - A type present in both models but in different files shows `base_file` and `head_file`; identical content in different files is still unchanged.
    - Builder duplicate policy: two types with the same id get ids `class X` and `class X#2` in (file ordinal, start_byte) order; two members with the same key in one type get `key` and `key#2`; the colliding ids are recorded on `ModelFile.duplicates` (strings such as `class shop::X (2 definitions)`, ordinal sorted).
    - Diff warnings, per side prefixed `base:` or `head:`: `N file(s) with parse errors` when N is above zero, `N file(s) not modelled` when above zero, and `duplicate <entry>` for each duplicates entry; no warning when all counts are zero.
    - Shuffling the type and member order of either input model never changes the resulting `DiffFile`; two empty models give zero counts and an empty `types` list.
  </behavior>

Keep ordering ordinal everywhere (`StringComparer.Ordinal`) and never depend on input order or on dictionary enumeration order (T-01-17).   <behavior>
    - Extensions .h .hpp .hh .hxx .cpp .cc .cxx are in scope, ordinal and case-insensitive (`A.CPP` yes); `.c`, `.cs`, `.hpp.bak`, `.txt` and a file with no extension are not.
    - With no globs every in-scope extension qualifies; with globs a path must match at least one (OR): `src/**`, `**/*.h`, `include/shop/*.h` and two globs together behave as documented by FileSystemGlobbing, with `/` separators and ordinal case-sensitive matching.
    - A glob that matches no changed file yields a successful run with zero types and a `files` list that is empty.
    - End to end on a synthetic repository where two directories change: with no `--include` both directories' types appear; with `--include "include/a/**"` only that directory's types and only its files appear in the models; with two `--include` flags in either order the five output files are byte-identical.
    - Only changed files are extracted (D-10): a C++ file unchanged between the commits does not appear in any model's `files` list; a file whose only change is the executable bit does not appear either; a deleted file appears in the base model only, an added file in the head model only.

  </behavior>
