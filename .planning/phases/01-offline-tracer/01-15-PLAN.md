<objective>
Close the one root cause behind the three failed truths of `01-VERIFICATION.md` (status gaps_found, 13/18): truth 2 (a run never changes the repository it reads), truth 7 (an `--out`, `-Out` or `-LogPath` reached through a link or junction into the repository is refused) and truth 16 (the doc comments name exactly what remains unresolved). Plans 01-13 and 01-14 put a one-entry denylist (the volume GUID spelling) on the raw link target in `FinalPath.Step` (C#) and `Resolve-FinalPathStep` (PowerShell). A junction whose substitute name is `\??\GLOBALROOT\Device\HarddiskVolumeN\{repository}` slips through both: the runtime strips the NT prefix, the remainder reads as a relative path, it is joined to the link's parent, and the containment test finds no overlap. The verifier reproduced it unprivileged: `vdiff --out {junction}\outx` exited 0 and wrote five files into the repository; the script wrote its output and its log into the repository under both PowerShell hosts and noticed only afterwards (`repo-changed`). Creating such a junction needs no privilege.

Purpose: roadmap criterion 2 and decisions D-02 (read-only repository) and D-03 (output only under `--out`), threats T-01-28, T-01-41 and T-01-44. In the target product `--out` comes from pipeline code, so the form is a deliberate-construction hole, but the verifier recorded it as a gap, not a residual, because the owner chose to harden this class (option b of `01-UAT.md` test 1).

**Planning-time probe (measured on the dev host, scratch directories only, junctions created and removed unprivileged; the validation reads the same facts back from the tests):**

| Substitute name written into the junction | .NET LinkTarget and PowerShell 7 Target | Windows PowerShell 5.1 Target | Traversable |
|-------------------------------------------|------------------------------------------|-------------------------------|-------------|
| `\??\GLOBALROOT\Device\HarddiskVolumeN\{dir}` | `GLOBALROOT\Device\HarddiskVolumeN\{dir}` | same | yes |
| `\Device\HarddiskVolumeN\{dir}` (no NT prefix) | first four characters dropped: `ice\HarddiskVolumeN\{dir}` | `\Device\HarddiskVolumeN\{dir}` intact | yes |
| `\??\UNC\localhost\X$\{dir}` | `UNC\localhost\X$\{dir}` | same | not on this host (loopback share), refused all the same |
| `\??\X:\{dir}` (what `mklink /J` writes) | `X:\{dir}` | `X:\{dir}` | yes |

A second probe wrote a junction whose substitute name is the GLOBALROOT spelling of a real directory and whose print name is a drive-letter decoy directory. All three readers (.NET `LinkTarget`, PowerShell 7 `Target`, Windows PowerShell 5.1 `Target`) reported the substitute name, never the decoy, and the junction still led to the real directory, so a drive-letter print name cannot be used to pass the allow-list. The tests pin that premise (decision R-4: the helper takes an optional print name).

Consequences, both decisive for the design: (1) the runtime never shows the NT prefix, so no product code could test for it, yet for every traversable non-drive form the reported text is not a drive-letter path; reading raw reparse data is therefore not needed, an allow-list on the reported text is enough. (2) The review's suggested name list (first segment GLOBALROOT, UNC, Device or Volume{) would still miss the bare-device spelling under .NET and PowerShell 7 (`ice\...`), so the rule must be an allow-list, not a list of names.

Decisions recorded in this plan (Claude's discretion; `01-CONTEXT.md` fixes only D-02, D-03 and D-09 for this area; R-numbers are new, K- and S-numbers belong to plans 01-13 and 01-14):

- **R-1, one allow-list on the reported target, both implementations.** On Windows a link is followed only when the target text the runtime reports is a drive-letter path (ASCII letter, colon, backslash). The test is applied before the target is combined with the link's parent and before `ResolveLinkTarget`. C# reuses `StartsWithDriveLetter`; the script reuses `Test-NonDriveRoot` (which is false off Windows). The volume GUID special cases of plans 01-13 and 01-14 are removed: a volume GUID target is not drive-lettered and is refused by the same rule. The final-path Win32 route named in `01-PATTERNS.md` stays declined for the reason plan 01-12 recorded (Windows PowerShell 5.1 cannot call it without compiling code), and the allow-list closes this gap without it; subst, mapped drives and 8.3 names remain the T-01-39 bound.
- **R-2, relative symbolic link targets on Windows are refused too (stated discretionary choice, surfaced to the orchestrator).** The text of a relative target cannot be told from a prefix-stripped absolute NT target, and the C# resolver cannot see the link kind without reading raw reparse data. No Windows test or product path relies on a relative target (`LinkScratch.Link` always makes junctions there; the relative branch is exercised only on Linux and macOS, where it stays). The cost is a refusal (exit 1, fixed message) of an `--out` behind a rare, privilege-needing relative symbolic link; the operator names the real path instead (T-01-47). It also refuses the targets written without a drive letter (`\foo`, `C:foo`) that were an open residual, so the re-worded bound must say it.
- **R-3, messages and reasons do not change.** The CLI keeps `FinalPath.UnsupportedRootMessage`; the script ends with reason script-error (a plain throw caught by the existing outer catch), as for the volume GUID case. The six-line vocabulary is untouched.
- **R-4, the junction fixture is a raw reparse-point write.** `LinkScratch.RawJunction` creates an empty directory and writes a mount-point reparse buffer with `DeviceIoControl` (`DllImport`, no `unsafe`, no csproj change), with an optional print name (default empty, as `mklink /J` writes for a plain junction); the NT-namespace tests pass a drive-letter decoy as the print name to pin the print-name premise above. It needs no privilege and is registered in the same list `Dispose` removes first, as links, non-recursively. `LinkScratch.NtSubstituteName` builds the spellings; the device name comes from `QueryDosDeviceW` for the sandbox drive at run time, so no machine value is committed.
- **R-5, the unreproducible symbolic link form is manual-only.** The reviewer's `\??\UNC\host\share` symbolic link needs a privilege the dev host lacks. A junction with a `\??\UNC\localhost\X$\...` substitute name reports the same relative-looking text on both hosts, so it is pinned at resolver level, and the real symbolic link check is added to the manual-only table of `01-VALIDATION.md`.
- **R-6, scope of the housekeeping.** Included: WR-02 (necessity, `01-REVIEW.md`, verifier advisory: drop the second pure-text namespace test on the log path) and IN-01 (remove the stale public handoff). Flagged to the orchestrator, not edited here: `01-UAT.md` test 1 (still `[pending]`, resolved by 01-13/01-14/01-15), `01-SECURITY.md` (T-01-41 and T-01-44 are re-opened by the verification and need the next `/gsd-secure-phase`; AR-04's wording lists a residual that this plan closes), `01-REVIEW-DISPOSITION.md`, `REQUIREMENTS.md` status (reverted to Gaps Found on purpose by commit aa94c91; the orchestrator sets Complete after re-verification), `STATE.md`. `ROADMAP.md` gets only the plan listing for this plan, added at planning time and committed by the orchestrator.
