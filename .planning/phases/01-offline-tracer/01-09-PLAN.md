  <name>Task 1: Install pinned mermaid-cli and write the local check script</name>
  <precondition>`.planning/phases/01-offline-tracer/01-03-SUMMARY.md` exists and holds a line starting `package-checkpoint: approved` (or a `pin`-style line with versions); `node --version` reports 22.13 or newer; a Chrome, Chromium or Edge browser exists on this machine.</precondition>
  <files>tools/mermaid-check/package.json, tools/mermaid-check/package-lock.json, tools/mermaid-check/check.mjs</files>
  <action>
Read the `package-checkpoint:` line in the plan 01-03 SUMMARY and take the exact versions of `@mermaid-js/mermaid-cli` and `puppeteer` from it; install nothing else and no other version (the line is the checkpoint's recorded decision; plan text elsewhere only quotes the offered defaults, 12.2.0 and 25.17.0). Create `tools/mermaid-check/package.json` as a private package, then run `npm install --save-exact --ignore-scripts --prefix tools/mermaid-check @mermaid-js/mermaid-cli@<version> puppeteer@<version>` once (install scripts stay off: puppeteer's browser download is not wanted, the machine's own browser is used; T-01-SC, T-01-21). Commit `package.json` and `package-lock.json`; every later install is `npm ci --ignore-scripts`. `check.mjs` takes one `.mmd` path. It finds a browser from env VDIFF_MERMAID_BROWSER, else the first existing candidate for the platform (Windows: Chrome and Edge under both Program Files folders; Linux: google-chrome, chromium, chromium-browser on PATH; macOS: the Chrome app bundle); none found means one line on stderr and exit code 3, which is distinct from a syntax failure. It writes a Puppeteer config JSON into a fresh temp directory with that `executablePath` (the launch arguments gain `--no-sandbox` only when env VDIFF_MERMAID_NO_SANDBOX is set, for root shells on Linux; default launches with the sandbox, T-01-22), runs mermaid-cli's `src/cli.js` through `process.execPath` with `spawnSync` and no shell (arguments: `-p`, config, `-i`, the file, `-o`, an svg in the temp directory), enforces a 120 s timeout, deletes the temp directory, and exits with mermaid-cli's exit code (1 on a syntax error), printing `mermaid-check: FAILED` and at most five lines of its stderr on failure. It makes no network request of its own and never posts anything (T-01-21; mermaid-cli renders locally).
  </action>
