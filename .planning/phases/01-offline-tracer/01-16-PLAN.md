**Planning-time probe (measured on the dev host with scratch directories only, under Windows PowerShell 5.1 and PowerShell 7; the tests of this plan re-assert the facts the design leans on):**

| Question | Result |
|----------|--------|
| Directory handle open, share read plus write (no delete sharing): rename the directory, its parent, its grandparent; delete the empty directory | all four refused (the directory: sharing violation, IOException; the ancestors and the delete: access denied) |
| Same handle opened with delete sharing | the directory itself can be renamed and deleted; parent and grandparent renames are still refused (an open handle on a descendant blocks ancestor renames whatever the share mode) |
| An open file (share none, with or without delete-on-close, or share read plus write) inside the directory | directory, parent and grandparent renames all refused (a held file would also freeze the chain, but it leaves a file in the output directory; a directory handle does not) |
| A link entry in the typed path (a junction to a real directory), handle on the target held: delete the link entry and create it again pointing elsewhere | SUCCEEDS; a write by the typed name then lands in the new target, a write by the handle's final path lands in the held directory. Holding is therefore not enough: every file operation must use the final path of the handle |
| GetFinalPathNameByHandleW, flags 0, on a directory opened through a junction and with a different letter case | the extended-length prefix, the drive letter and the real path with its real casing, the link followed |
| File and FileStream I/O with the prefixed and with the prefix-stripped form of that path | both work, on both hosts |

Decisions recorded in this plan (Claude's discretion; `01-CONTEXT.md` fixes only D-02, D-03 and D-09 for this area; H-numbers are new, R-, K- and S-numbers belong to earlier plans):

- **H-1, hold plus final path plus judgement, in that order of dependence.** Windows: open the final output directory with CreateFileW, desired access GENERIC_READ, share read plus write, open-existing, backup semantics, and no open-reparse-point flag (a link at the last component is followed, so what is judged is where files would really land). Read the final path from the handle with GetFinalPathNameByHandleW. Judge it. Create and move every file by it. The product owner's "and/or" (hold the directory, and/or verify each created temp file by handle) is met by the directory handle: every file operation happens inside the directory whose final path was judged while it is held, so a per-file handle check would add nothing.
- **H-2, acquisition order.** Pipeline, text check, then: open and judge the deepest existing ancestor (the anchor), create the missing directories under the anchor's final path, open and judge the leaf, release the anchor. A refusal after creation removes the directories this call created (non-recursive, bottom-up). The truth is worded "no file is created or written", not "nothing is created", because a directory created through a swap before the leaf is judged is removed afterwards, not prevented. Acquisition stays after the pipeline so `--out` is absent or untouched when the pipeline fails (T-01-28).
- **H-3, final-path forms.** Drive-letter: prefix removed, judged. UNC (the form a mapped drive letter or a share reports): accepted, not judged, behaviour unchanged. Anything else: `FinalPath.UnsupportedRootMessage`. Refusing UNC would regress a working `--out` on a mapped drive and edge into AR-04, which the product owner kept.
- **H-4, non-Windows.** No handle is held. The resolved path is judged before and after the directories are created, files are written by the resolved path, and the bound is stated (truth 6). A native openat-style route is not used: it needs per-platform struct layouts for no gain over the stated bound on the platforms where `--out` comes from pipeline code.
- **H-5, test seam.** `CliHooks` (AfterPipeline, AfterSecondCheck, AfterHeld with the held path). A hook records what happened into locals and never asserts: `CliApp.Run` catches every exception and reports exit 1, so an assertion inside a hook would be swallowed and fail the test with no message. If a hook's attempt to rename succeeds (the red run), it moves the directory straight back so the run can continue.
- **H-6, scope guard.** The judgement compares what the operating system reports for the open handle with the protected roots as `FinalPath.Resolve` renders them. For a spelling that the text walk does not fold the two can differ. That is unplanned and unclaimed: the executor writes no test, comment or truth about it and records any observation in the SUMMARY under "Incidental".
- **H-7, handed to plan 01-17.** `-Out` against the vdiff repository root, which the CLI does not know, travels to the CLI in the environment in plan 01-17 (D-03 fixes the argument list). The extension point is the `findRefusal` function this plan passes to `HeldDirectory.Create`.
- **H-8.** `OutputWriter.WriteAll` becomes `internal` (its only caller is `CliApp.Run`; tests use `Serialize`, which stays public).
