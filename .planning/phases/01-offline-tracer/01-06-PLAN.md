<objective>
Deepen the Rust sidecar from the tracer subset to the C++ coverage the phase promises, and prove macro blanking (D-05), span validity and honest labelling (ADR-001 consequences) through the real CLI.

Purpose: the tracer extracted only simple class and struct members. The real-repository run (plan 06) will meet enums, nested types, operators, export macros, odd encodings and unparseable regions. This plan makes those cases extract correctly or be labelled, and keeps the sidecar from crashing (TRC-02; SPK-02 evidence that the ADR-001 sidecar does the job).

Output: richer `extract.rs`, hardened `blank.rs` tests, cargo tests, and two CLI-level test classes.

  <name>Task 1: Full member and type coverage in the sidecar (enums, nested types, aliases, special members)</name>
  <files>extractors/cpp-ts/src/extract.rs, tests/Vdiff.Tests/Extraction/RichFixtureEndToEndTests.cs</files>
  <behavior>
    - `enum Color { Red, Green }` and `enum class E : unsigned char { X }` give a type of kind `enum` with `bases` holding the underlying type from the `base` field's own text (`unsigned char`, not its leaf `char`; C33; empty when none) and one member per enumerator (`kind` enumerator, `access` none, `key` the name, `signature` the enumerator text such as `B = 2`).
    - A class, struct or enum declared inside a class or struct is its own type whose `scope` includes the enclosing type (`shop::Box` as scope of `Mode`); a `field_declaration` that declares only a type yields no member; one that also declares a variable yields that variable as a field.
    - `using Item = std::pair<int, int>;` and `typedef int Handle;` inside a type give members of kind `alias`.
    - A `template_declaration` around a class or struct still yields the type under its plain name (template parameters are not tracked; a specialisation keeps its template arguments in the name, `Spec<int>`); a member template yields one member whose signature includes the template header.
    - Names: destructor `~Box`, operator `operator==`, call operator `operator()`, stream operator `operator<<` (these come from the node's own text, built in plan 01-01); constructors by their name; an `explicit` or `override` or `= 0` specifier stays in `signature`, not in `key`.
    - Conversion operators (C32): `operator bool() const;` and `operator std::string() const { ... }` are an `operator_cast` node under a `declaration` or `function_definition`, with a `type` field and an `abstract_function_declarator` holding `parameters` and the `type_qualifier`; there is no `function_declarator` on this path. The member is a method named from the text of `operator` through the type (`operator bool`, `operator std::string`), with key `operator bool() const` and the whole declaration in `signature`.
    - Members and nested types under `preproc_if`, `preproc_ifdef` and `preproc_else` inside a class body are found, including a nested enum (plan 01-01 built the descent; this plan adds the nested kinds).
    - Known gaps (D-11, C36), as characterisation tests named `known_gap_*`: a `typedef struct { int a; } Name;` yields no type named `Name` and the file is otherwise extracted normally; a class containing a macro call with arguments (`DECLARE_X(Foo)` before a real member) still yields the class and the real member, and any bogus member the grammar produces for the macro call is not asserted. Both are recorded as labelled limitations, not fixed in Phase 1.
    - A function-pointer field such as `int (*cb)(int);` is kind field; `int n_, m_;` gives two fields; a `const` and a non-const overload have different keys; friend, using and static_assert children yield nothing.
    - An in-class function body and a constructor initializer list are excluded from `signature`.
    - Unions are not extracted (kind is limited to class, struct, enum).
    - Output order is deterministic: types in source order, parents before nested types.
  </behavior>

  <name>Task 2: Macro blanking proven at byte level and through --blank (D-05)</name>
  <files>extractors/cpp-ts/src/blank.rs, tests/Vdiff.Tests/Extraction/BlankingEndToEndTests.cs</files>
  <behavior>
    - Length preserved: output length equals input length for every input; only bytes inside a matched macro change, and they become spaces.
    - Whole word only: `EXPORT_API_X`, `MY_EXPORT_API` and `EXPORT_APIS` are untouched when `EXPORT_API` is blanked; a name that is a prefix of another (`EXPORT` and `EXPORT_API`) blanks each correctly; matching is case-sensitive.
    - Lines whose first non-blank byte is `#` are untouched, including an indented `  #define`; a macro at the very start or end of the file is blanked; adjacent and repeated macros on one line are all blanked.
    - Multi-byte UTF-8 next to a macro is never altered; a file with a byte-order mark keeps it, and spans of types after it are offset by exactly 3 bytes.
    - End-to-end (CLI): a synthetic head commit with `class EXPORT_API Foo : public Base { ... }` run without `--blank` yields no type with id `class Foo`; with `--blank EXPORT_API` it yields `class Foo` with base `Base` and its members; repeating `--blank` for two macros records `macros_blanked` sorted and distinct in `head.model.json` and `base.model.json`; a member declared after a macro on the same line has `start_byte` equal to its true UTF-8 offset in the committed file bytes.
  </behavior>
