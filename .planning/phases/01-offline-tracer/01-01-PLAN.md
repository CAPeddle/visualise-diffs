<objective>
Build the Rust tree-sitter sidecar from ADR-001: a bounded, stdin-driven process that turns file bytes into a syntax-only list of C++ types and members, after length-preserving macro blanking, with a per-file parse deadline and a per-file status.

Purpose: the .NET side (plans 01-02 and 01-03) talks to this process only through the JSON protocol defined here, so the sidecar can be built and proven alone, in parallel with the .NET core read path. ADR-001 (accepted by the PO on 2026-11-16) chose this packaging; this plan puts it to work and keeps its pinned dependency graph (SPK-02) and its C++ extraction (TRC-02) behind a stable contract. Per D-11 the protocol carries a per-file `status` so a timed-out file is labelled, never silently empty.

Output: the `extractors/cpp-ts` crate (8 files in this plan including the repository ignore rules), with an in-crate test suite.

Tracer-first note: the phase's end-to-end tracer is plan 01-03 task 1. This plan and plan 01-02 are its two prerequisites, built in parallel, each with its own runnable proof (the cargo suite here; git-to-bytes reading and the client protocol in 01-02). Plans 01-06 (sidecar depth) and later harden what is created here.

Modules: `main.rs`, `protocol.rs`, `blank.rs`, `extract.rs`.

Protocol v0 (stdin manifest; the sidecar never opens a repository path, T-01-04): stdin is one UTF-8 JSON header line ended by a line feed, then the raw bytes of each listed file back to back. Header: `schema` "vdiff-cpp-ts-request/v0", `blank` (macro names), `parse_budget_ms` (optional), `files` (list of `path` and `len`). Paths are echoed labels only. Every rejection in the behaviour list above is exit 2 with a fixed stderr message that never includes file content or the header text (T-01-27). Use checked arithmetic for the total length. Install a panic hook that prints one fixed line and no payload, so content cannot leak through a panic message. The response is written to stdout as UTF-8 bytes (ADR-001: explicit UTF-8).

Deadline (T-01-32; D-11): tree-sitter 0.27.0 has no timeout setter, only `parse_with_options` with a `ParseOptions::progress_callback`. In `extract.rs` provide `parse_bounded(parser, bytes, budget)`: compute a wall-clock deadline, parse through `parse_with_options` with a progress callback that returns `ControlFlow::Break` once the deadline has passed, and when the call returns None call `parser.reset()` before the parser is used again (a cancelled parser otherwise resumes the abandoned parse on its next use, measured), and report status "timeout". A parse failure that is not a deadline is status "error"; success is "ok". Never `unwrap()` the parse result. Write the tests in `extract::deadline` (at least three: the timeout label, the reset-then-correct-parse test, and a generous budget returning "ok").

`blank.rs` is the length-preserving pass from the S2 trial (D-05) with `blank::tests` (at least six tests: length preserved, preprocessor line untouched including an indented one, partial word untouched, a macro at the start and at the end of the input, adjacent macros, multi-byte UTF-8 next to a macro untouched). `main.rs` exposes a pure `run(input: &[u8]) -> Result<Vec<u8>, Failure>` used by `main` and by in-crate tests; it applies the blank pass to each file's bytes, parses with the pinned language through `parse_bounded`, counts error nodes, and calls `extract::extract_types`, which in this task returns an empty list (task 2 implements it). Files are parsed in parallel with rayon `par_iter` and `map_init` (one parser per thread) on a pool with a 64 MiB thread stack, collected in input order. Version constants live in `main.rs`; add a test that reads Cargo.toml and Cargo.lock through `include_str!` and asserts the constants equal the pins. `protocol::tests` covers each rejection, the `parse_budget_ms` range and the empty-files response.

  <files>extractors/cpp-ts/src/extract.rs</files>
  <behavior>
    - A `class_specifier` or `struct_specifier` with both a name and a body is a type (forward declarations are not); kind is class or struct. Types are reached by a whitelist descent (C5), not by walking every node: `translation_unit`, `namespace_definition` and its `declaration_list`, `template_declaration`, `linkage_specification` and its body, `preproc_if`, `preproc_ifdef`, `preproc_else` and the elif variants (C4), `declaration`, `type_definition`, class and struct bodies for nested types, and `ERROR` nodes (so a type that parsed beside a syntax error is still returned). Function bodies are not entered, so a local class never appears with a wrong scope.
    - Scope is the chain of enclosing namespace names (`(anonymous)` when a namespace has no name, `shop::billing` for a nested specifier) followed by enclosing type names, joined with `::`.
    - `bases` holds each base entry's text without access keyword or `virtual`, whitespace collapsed.
    - Members come from the type body in order and also from `preproc_if`, `preproc_ifdef`, `preproc_else` and elif children inside the body (C4); an access specifier sets the current access (private for a class, public for a struct); a field, declaration or function definition child yields one member per declarator (so `int n_, m_;` gives two); other child kinds yield nothing in this plan; a declarator shape this plan does not handle (a conversion operator, plan 01-06) yields no member rather than a wrong one.
    - Names (C2, C3): follow `declarator` fields through `pointer_declarator`, `array_declarator`, `parenthesized_declarator` and `function_declarator`; a `reference_declarator` has no `declarator` field, so look for the wrapped `function_declarator` or name among its named children; for `destructor_name` and `operator_name` the name is that node's own text (`~Gadget`, `operator==`, `operator()`), not its innermost leaf. Kind is method when a `function_declarator` lies on the path and its own declarator is a plain name, destructor name or operator name; else field (so `int (*cb)(int);` is a field).
    - `key` of a method is the name immediately followed by the parameter-list text, then a single space before each trailing cv-qualifier (`size() const`, `grow(int by)`, `~Widget()`), with whitespace runs collapsed to one space (C6); `key` of a field is its name. `signature` is the member text up to the start of its `body` (`compound_statement`) or `field_initializer_list`, else to its end, so `= 0`, `= default`, `= delete` and field default values stay in; trailing semicolon removed, whitespace collapsed, cut at 4096 bytes on a character boundary (C7).
    - Text is taken with lossy UTF-8 conversion, never an empty string on invalid bytes (C7); spans are UTF-8 byte offsets and 1-based lines, exact after a byte-order mark, a Latin-1 byte or non-ASCII text; ordering is source order, parents before nested types.
  </behavior>
