<objective>
Build the Rust tree-sitter sidecar from ADR-001: a bounded, stdin-driven process that turns file bytes into a syntax-only list of C++ types and members, after length-preserving macro blanking.

Purpose: the .NET side (plans 01-02 and 01-03) talks to this process only through the JSON protocol defined here, so the sidecar can be built and proven alone, in parallel with the .NET core read path. ADR-001 (accepted by the PO on 2026-11-16) chose this packaging; this plan puts it to work and keeps its pinned dependency graph (SPK-02) and its C++ extraction (TRC-02) behind a stable contract.

Output: the `extractors/cpp-ts` crate (8 files in this plan including the repository ignore rules), with an in-crate test suite.

Tracer-first note: the phase's end-to-end tracer is plan 01-03 task 1. This plan and plan 01-02 are its two prerequisites, built in parallel, each with its own runnable proof (the cargo suite here; git-to-bytes reading and the client protocol in 01-02). Plans 01-06 (sidecar depth) and later harden what is created here.

  <behavior>
    - A request whose header names a wrong schema, exceeds 8 MiB, names a macro that is not an ASCII identifier, promises a total length over 512 MiB, promises lengths whose sum overflows 64 bits, or is followed by fewer bytes than promised gives exit 2 and a stderr message without file content; an empty `files` list gives a valid empty response.
    - The response is one JSON object with `schema` "vdiff-cpp-ts/v0", `tree_sitter` "0.27.0", `tree_sitter_cpp` "0.23.4", `macros_blanked` (request names, sorted, distinct) and `files` in request order, each with `path`, `error_nodes` and `types`.
    - Blanking replaces whole-word ASCII macro names with the same number of spaces on raw bytes, leaves lines whose first non-blank byte is `#` untouched, leaves partial words (`EXPORT_API_X`, `MY_EXPORT_API`) untouched, and never changes the length.
    - `error_nodes` counts ERROR and MISSING nodes in each file's tree.
    - A cargo test compares the version constants with the `=` pins in Cargo.toml and the entries in Cargo.lock.
  </behavior>
  <action>
`.gitignore` lists bin/, obj/, target/, node_modules/, TestResults/, .vs/, *.user and the run-output directories `/out/`, `/vdiff-out*/` and `*.vdiff-out/`, so run output cannot reach this PUBLIC repository (D-09, T-01-03). `.gitattributes` pins `*.sh`, `Cargo.lock`, `package-lock.json` and `*.mjs` to `text eol=lf` (machine rule: shell scripts and lock files stay LF); add no catch-all `text=auto` rule.

Seed `extractors/cpp-ts` from `docs/spikes/S2-trial/B` (D-04, ADR-001): package and binary name `vdiff-cpp-ts`, version 0.0.0, edition 2021, the same dependencies and release profile (`tree-sitter =0.27.0`, `tree-sitter-cpp =0.23.4`, rayon 1, serde with derive, serde_json; keep rayon). Copy `Cargo.lock` from the S2 trial and change ONLY the root package name entry from `s2b` to `vdiff-cpp-ts`; every other entry stays byte-identical so the graph is the one ADR-001 trialled. `cargo build --release --locked` must pass (cold build about 70 s). If `--locked` rejects the rename, run `cargo build --release` once and confirm only the root package entry moved. Modules: `main.rs`, `protocol.rs`, `blank.rs`, `extract.rs`.

Protocol v0 (stdin manifest; the sidecar never opens a repository path, T-01-04): stdin is one UTF-8 JSON header line ended by a line feed, then the raw bytes of each listed file back to back. Header: `schema` "vdiff-cpp-ts-request/v0", `blank` (macro names), `files` (list of `path` and `len`). Paths are echoed labels only. Every rejection in the behaviour list above is exit 2 with a fixed stderr message that never includes file content or the header text (T-01-27). Use checked arithmetic for the total length. Install a panic hook that prints one fixed line and no payload, so content cannot leak through a panic message. The response is written to stdout as UTF-8 bytes (ADR-001: explicit UTF-8).

`blank.rs` is the length-preserving pass from the S2 trial (D-05) with `blank::tests` (at least six tests: length preserved, preprocessor line untouched including an indented one, partial word untouched, a macro at the start and at the end of the input, adjacent macros, multi-byte UTF-8 next to a macro untouched). `main.rs` exposes a pure `run(input: &[u8]) -> Result<Vec<u8>, Failure>` used by `main` and by in-crate tests; it applies the blank pass to each file's bytes, parses with the pinned language, counts error nodes, and calls `extract::extract_types`, which in this task returns an empty list (task 2 implements it). Files are parsed in parallel with rayon `par_iter` and `map_init` (one parser per thread) on a pool with a 64 MiB thread stack, collected in input order. Version constants live in `main.rs`; add a test that reads Cargo.toml and Cargo.lock through `include_str!` and asserts the constants equal the pins. `protocol::tests` covers each rejection and the empty-files response.

<task type="auto" tdd="true">
  <name>Task 2: Type and member extraction (tracer subset)</name>
  <files>extractors/cpp-ts/src/extract.rs</files>
  <behavior>
    - A `class_specifier` or `struct_specifier` with both a name and a body is a type (forward declarations are not); types are found at any depth; kind is class or struct.
    - Scope is the chain of enclosing namespace names (`(anonymous)` when a namespace has no name, `shop::billing` for a nested specifier) followed by enclosing type names, joined with `::`.
    - `bases` holds each base entry's text without access keyword or `virtual`, whitespace collapsed.
    - Members come from the type body in order; an access specifier sets the current access (private for a class, public for a struct); a field, declaration or function definition child yields one member per declarator (so `int n_, m_;` gives two); other child kinds yield nothing in this plan.
    - Names: the innermost leaf's text, so a destructor is `~Name` and an operator is `operator==`; kind is method when a function declarator whose own declarator is a plain name lies on the path, else field.
    - `key` of a method is the name immediately followed by the parameter-list text, then a single space before each trailing cv-qualifier (`size() const`, `grow(int by)`, `~Widget()`); `key` of a field is its name; `signature` is the member text up to its body or initializer list, trailing semicolon removed, whitespace collapsed, cut at 4096 bytes.
    - Spans are UTF-8 byte offsets and 1-based lines, exact after a byte-order mark, a Latin-1 byte or non-ASCII text; ordering is source order, parents before nested types.
  </behavior>
  <action>
Implement `extract::extract_types` with `extract::tests` (at least eight tests using small inline sources). The tree shapes were measured with the pinned grammar while planning: a type's `name` and `body` are fields; the body is a `field_declaration_list`; `access_specifier` nodes are its children; method declarators are `function_declarator` nodes whose `declarator` is a `field_identifier`, `identifier`, `destructor_name` or `operator_name`, with a `parameters` field holding the `parameter_list` and `type_qualifier` children for const; pointer and reference declarators wrap the function declarator and a field may have several `declarator` children. Verify any rule that does not hold by printing a tree inside a test while developing, then keep only assertions. Recursion runs on the large-stack pool from task 1; the depth cap and richer member kinds (enums, nested types, aliases, templates, conversion operators) belong to plan 01-06 and must not be started here. Do not name any real product in test sources (D-09).
  </action>
