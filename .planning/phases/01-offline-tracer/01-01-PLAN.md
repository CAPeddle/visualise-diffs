SIDECAR CRATE (D-04, ADR-001). Seed `extractors/cpp-ts` from `docs/spikes/S2-trial/B`: package and binary name `vdiff-cpp-ts`, version 0.0.0, edition 2021, the same dependencies and release profile (`tree-sitter =0.27.0`, `tree-sitter-cpp =0.23.4`, rayon 1, serde with derive, serde_json; keep rayon). Copy `Cargo.lock` from the S2 trial and change ONLY the root package name entry from `s2b` to `vdiff-cpp-ts`; every other entry stays byte-identical so the graph is the one ADR-001 trialled. `cargo build --release --locked` must pass (cold build about 70 s). If `--locked` rejects the rename, run `cargo build --release` once and confirm only the root package entry moved. Modules `main.rs`, `protocol.rs`, `blank.rs`, `extract.rs`.
- Protocol v0, a stdin manifest: no repository path is ever opened by the sidecar (T-01-04). Stdin is one UTF-8 JSON header line ended by a line feed, then the raw bytes of each listed file back to back. Header: `schema` "vdiff-cpp-ts-request/v0", `blank` (macro names), `files` (list of `path` and `len`). The sidecar exits 2 with a stderr message that never contains file content on: wrong schema, header over 8 MiB, a macro name that is not an ASCII identifier, a total length over 512 MiB, or stdin shorter than the lengths promise. Paths are echoed labels, never opened.
- Response, one JSON object on stdout written as UTF-8 bytes: `schema` "vdiff-cpp-ts/v0", `tree_sitter` "0.27.0", `tree_sitter_cpp` "0.23.4" (constants, with a cargo test that compares them with the `=` pins in `Cargo.toml` and the entries in `Cargo.lock` through `include_str!`), `macros_blanked` (request list, sorted, distinct), and `files` in request order, each with `path`, `error_nodes` (count of ERROR and MISSING nodes in the tree) and `types`.
- `blank.rs`: the length-preserving pass from the S2 trial on raw bytes (whole-word ASCII macro names replaced by spaces; lines whose first non-blank byte is `#` skipped) plus cargo tests for length preserved, preprocessor line untouched, partial word untouched (D-05).
- `extract.rs`, tracer subset. Parse the blanked bytes; files in parallel with rayon `par_iter` and `map_init` (one parser per thread), collected in input order, on a rayon pool built with a 64 MiB thread stack. A type is a `class_specifier` or `struct_specifier` with both a `name` and a `body` field (forward declarations skipped), found at any depth. Scope is the chain of enclosing namespace names (`namespace_definition` name text; `(anonymous)` when absent) then enclosing type names, joined with `::`. Per type: `kind` (class or struct), `name`, `scope`, `bases` (text of each base entry without access keyword or virtual, whitespace collapsed), `start_byte`, `end_byte` (UTF-8 byte offsets), `start_line`, `end_line` (1-based), `members`.
- Members: walk the named children of the type body in order. An `access_specifier` child sets the current access (default private for class, public for struct). A `field_declaration`, `declaration` or `function_definition` child yields one member per `declarator` field child; other child kinds yield nothing here (nested types, enums, aliases, friends and using are plan 01-03). For each declarator follow `declarator` fields through pointer, reference, array, parenthesized and function declarators to the innermost leaf; `name` is that leaf's text, so a destructor gives `~Name` and an operator gives `operator==`. `kind` is method when a `function_declarator` lies on that path and its own declarator is a plain name leaf, else field. For a method `key` is name + the `parameter_list` text + any `type_qualifier` text directly under the function declarator, joined by single spaces; for a field `key` is name. `signature` is the member node's text from its start to the start of its body or `field_initializer_list` (whichever is first), else to its end, with a trailing semicolon removed; for a multi-declarator field it is the type text, a space, and that declarator's text. Collapse whitespace runs to one space and cut `signature` at 4096 bytes. Each member also has `access`, `start_byte`, `end_byte`, `start_line`, `end_line`.

CORE (names fixed here so plans 02 to 05 can extend them; namespace root `Vdiff.Core`).
- `VdiffException`: every expected failure; message only, never file content.
- `Process.BoundedProcess.Run(file, args, limits, stdin, env)` returns `ProcessResult(ExitCode, Stdout, StderrTail)`. Argument list only (ProcessStartInfo.ArgumentList), no shell, UseShellExecute false. Stdin is written on its own task then closed; stdout and stderr are drained concurrently as raw bytes. `ProcessLimits(Timeout, MaxStdoutBytes, MaxStderrBytes)`: on timeout or stdout over the cap, kill the whole process tree and throw `VdiffException` naming the limit; stderr beyond its cap is drained and discarded (T-01-05).
- `Git.GitObjectReader(repoPath)` (D-02). Every call is `git --no-optional-locks -C <repo> ...` through BoundedProcess; child environment drops GIT_DIR, GIT_WORK_TREE, GIT_INDEX_FILE, GIT_COMMON_DIR, GIT_NAMESPACE and GIT_EXTERNAL_DIFF and sets GIT_OPTIONAL_LOCKS=0, GIT_TERMINAL_PROMPT=0 and GIT_NO_LAZY_FETCH=1 (a partial clone must fail offline, not fetch and write into `.git`; T-01-08). `ResolveCommit(hex)` accepts only 7 to 64 hexadecimal characters, then runs `rev-parse --verify --quiet --end-of-options <hex>^{commit}` and returns the full id. `ListChanged(baseOid, headOid)` runs `diff-tree -r -z --raw --no-renames --no-abbrev <base> <head>` and parses the NUL-separated records (`:mode mode oid oid status`, NUL, path, NUL), keeping only entries whose side is a regular file (mode 100644 or 100755), dropping entries whose two blob ids are equal (a mode-only change; D-10 skips files whose base and head blobs are identical), decoding paths as strict UTF-8 (undecodable paths become unmodelled with reason `non-utf8-path`). D-02 names `git diff --name-status`; this uses the plumbing form of the same comparison because it never runs external diff drivers or textconv, returns both blob ids in one call and is NUL-delimited. The intent of D-02, reading only git objects and writing nothing, is unchanged. `ReadBlobs(oids, maxBlobBytes)` first runs `cat-file --batch-check` to learn sizes and types, then `cat-file --batch` for the blobs within the cap (4 MiB each); oversized or missing objects become unmodelled with reason `too-large` or `object-missing`. Ids sent to git stdin are re-validated as 40 or 64 hex characters. `ToplevelOrGitDir()` returns the work-tree root (or the absolute git dir for a bare repository) for the containment check.
- `Scope.ScopeFilter(includeGlobs)`: `IsInScope(path)` is true for extensions .h .hpp .hh .hxx .cpp .cc .cxx (ordinal, case-insensitive) and, when globs were given, at least one `FileSystemGlobbing` match (D-10).
- `Extraction.CppSidecar`: `Locate()` returns a `SidecarCommand(File, LeadingArgs)` from, in order, env var VDIFF_CPP_TS, `vdiff-cpp-ts` beside the app, `extractors/cpp-ts/vdiff-cpp-ts` beside the app, then a walk up from the app directory to the first folder holding `extractors/cpp-ts/Cargo.toml` and its `target/release/vdiff-cpp-ts` (`.exe` on Windows); not found is a `VdiffException` that names the cargo build command. `Extract(files, blank, command, limits)` writes the manifest, reads and parses the response, checks its `schema`, and treats non-zero exit, bad JSON or a wrong schema as a `VdiffException`. `SidecarLimits` defaults: 120 s, 64 MiB stdout, 1 MiB stderr. Invoked once per commit, even with zero files, so the version metadata is always present (ADR-001 metadata).
- `Model.ModelTypes`: records serialised with snake_case names (property order is declaration order). `ModelFile`: `schema` "vdiff-model/v0-tracer", `commit`, `extraction` {`extractor` "cpp-ts", `mode` "syntax-only", `tree_sitter`, `tree_sitter_cpp`, `macros_blanked`}, `files` [{`path`, `error_nodes`}], `unmodelled` [{`path`, `reason`}], `types`. `TypeModel`: `id`, `fqn`, `kind`, `name`, `scope`, `file`, `bases`, `span`, `members`. `MemberModel`: `key`, `name`, `kind`, `access`, `signature`, `span`. `SourceSpan`: the four span numbers. `DiffFile`: `schema` "vdiff-diff/v0-tracer", `base`, `head`, `summary` {`types` {added, removed, modified, unchanged}, `members` {added, removed, modified}}, `warnings`, `types` (only changed types). `TypeDiff`: `id`, `fqn`, `kind`, `state`, `base_file`, `head_file`, `bases` {added, removed}, `members`. `MemberDiff`: `key`, `name`, `state`, `access_before`, `access_after`, `signature_before`, `signature_after` (nulls omitted). Type states added, removed, modified, unchanged.
- `Model.ModelBuilder.Build(commit, response, unmodelled, macros)` makes the `ModelFile`: `fqn` is scope + `::` + name (name alone when scope is empty), `id` is kind + a space + fqn; types are sorted by id and members by key, ordinal; duplicate ids (type or member key) are made unique by suffixing `#2`, `#3` in source order so a run never crashes on repeated definitions.
- `Diff.ModelDiffer.Diff(baseModel, headModel)` matches types by id (D-07): only in head is added with all members added; only in base is removed with all members removed; in both compares `bases` as sets and members by key (only in head added, only in base removed, in both with different `access` or `signature` modified). A type with any change is modified, else unchanged and counted but not listed. Warnings state, per side, the number of files with parse errors and the number not modelled. Everything ordinal-sorted.
- `Output`: `CanonicalJson.Serialize` (indented, `NewLine` set to LF, snake_case, nulls omitted, trailing LF). `MermaidWriter.Render(DiffFile)` emits `classDiagram`, then per changed type, ordered by id, `class <id>["<fqn>"]:::<state> {` with one line per changed member of the form visibility char (+ public, # protected, - private), the signature, a space and `[<state>]`, then a `classDef` line each for added, removed and modified using the S1 colours; the class id is the fqn with every character outside letters, digits and underscore replaced by an underscore, made unique; escape `{`, `}` and `~` in member text and `"` in labels with look-alike characters (U+2774, U+2775, U+223C, U+2033). `HtmlWriter.Render(DiffFile, mermaid)` returns one self-contained page: charset meta, inline CSS, a summary line, the warnings, a table of changed types and members with their states, and the Mermaid text in an escaped pre block; every value from the repository is passed through `WebUtility.HtmlEncode`; no script element, no external URL, no remote font or image (T-01-06). `OutputWriter.WriteAll(outDir, baseModel, headModel, diff, mermaid, html)` writes the five fixed file names as UTF-8 without BOM using LF; repository paths are never used as file names (T-01-04).
- `Cli.CliOptions.Parse(args)` (D-03): required `--repo`, `--base`, `--head`, `--out`, each once with a value; repeatable `--blank` (an ASCII identifier, at most 256) and `--include` (non-empty, no NUL, at most 512 chars, at most 64); `--help` prints usage to stdout and exits 0; any unknown argument is an error. `--base` and `--head` must match 7 to 64 hexadecimal characters (T-01-01). `Cli.CliApp.Run(args, stdout, stderr)` returns 0 or 1 (R27 contract), prints `vdiff: <message>` to stderr on failure and never prints file content. Flow: parse; require `--repo` to be an existing directory that git accepts; resolve both commits; compute the full `--out` path and refuse it when it lies inside the repository work tree or git dir or when it exists as a file (compare with OrdinalIgnoreCase on Windows, Ordinal elsewhere, on directory boundaries); `ListChanged`; keep in-scope C++ entries; for each side read blobs of that side's entries and call the sidecar (`--blank` names go in the header); build both models; diff; render; create `--out` only now and write all five files. A failure before the write leaves `--out` absent or untouched. `Program.Main` only calls `CliApp.Run` with the console writers.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| CLI arguments to git | `--repo`, `--base`, `--head` come from the user and reach `git` as argument values |
| analysed repository to vdiff | tree contents, paths and blobs are untrusted input, possibly hostile |
| vdiff to sidecar process | file bytes cross a process boundary; the child can hang, flood or crash |
| vdiff to `--out` | the only place vdiff may write |
| vdiff output to this public repository | private target content must never end up in a committed file |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |

| T-01-01 | Tampering | `CliOptions`, `GitObjectReader` argument handling | high | mitigate | Hex-only 7 to 64 character commit ids checked before any process starts, `rev-parse --verify --end-of-options`, ids re-validated before use, ProcessStartInfo.ArgumentList only, no shell anywhere; plan 02 adds hostile-argument tests |
