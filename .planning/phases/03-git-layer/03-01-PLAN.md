<objective>
Make the offline tracer analyse two exported trees instead of reading blobs straight from git objects (D-01, D-03, D-04), with the trees in a contained temporary directory that is always deleted unless `--keep-trees` asks otherwise (D-05, D-06), and with a missing object turning into exit 1 and the full-clone message (D-09, D-10). This is the phase's tracer: one change that runs through git plumbing, a new exporter, a held temp directory, the pipeline and the CLI, proven by an end-to-end CLI run, with every commit compiling and the suite green.

Purpose: Phase 2's UAT showed that reading the base side from git objects fails silently on a partial clone and turns base types into `added`. Exported whole trees are what Phase 4's whole-repository extraction needs, and the BAD-size check makes a partial clone fail loudly instead.

Output: `TreeExporter` and `TreeWorkspace`, the pipeline switched to exported trees, `--keep-trees`, tree-root containment, and the blob-batch reader removed.

Scope of this plan (later plans extend it, nothing here is provisional): rename pairs and hunks arrive in 03-04; path rules beyond the minimal traversal guard, case collisions, export tiers and the total and file-count limits in 03-05; shallow-clone messages in 03-06; both-side exclusion with side-coded reasons in 03-07; PR mode in 03-08. Until 03-07, a changed in-scope file the export skipped on one side is listed as unmodelled on that side with the export reason, exactly as the old blob reader did.
