<objective>
Harden what every child process inherits before the tool ever holds an access token, and give the test suite the scripted-repository helpers the rest of the phase needs.

Purpose: D-14 makes `SYSTEM_ACCESSTOKEN` part of the process environment in PR mode, and today `GitCommand.BuildEnvironment` copies the whole environment into every git child while `CppSidecar.Extract` passes no environment at all, so both would inherit it (research, REST client shape). Git's rename-limit warning is the only signal that rename detection stopped (D-20), and it is localised, so git must run in the C locale. The helpers are put in one early task so the later plans only call them.

Output: `ChildEnvironment`, the scrubbed git and sidecar environments, a `dump-env` fake-sidecar mode, and ten `SyntheticRepo` helpers with self-tests.

Executor notes:
- Per the user's standing instructions, dispatch every build and test run to a subagent; have it report only the summary line, the Total figure and failing test names.
- Use Glob, not `find | sort`, for file discovery.
- Before every commit, stage only the task's files and run `bash C:/projects/shared-copilot/docs/investigations/visualise-diffs/scripts/check-public-diff.sh --cached`; commit only on a line starting with `clean`.
- Wave 1 holds 03-01, 03-02 and 03-03, which share no file but all build `tests/Vdiff.Tests`. They run at once only in separate per-plan git worktrees, which is how execute-phase dispatches a parallel wave; when isolation resolves to none it runs the wave sequentially (frontmatter `coupling_justified`). An executor run by hand outside execute-phase must never build two plans in one working tree at once.
- A test that sets a process-wide variable carries `[Collection("sidecar")]` and restores it (EnvironmentScope). This plan's token test is a deliberate exception to "PR variables only through CliHooks": proving a child never sees the token needs the token in the real process environment.
- Prohibition recall breadcrumb: "the access token never reaches a child process" is canon (sensitive-data exposure); it is enforced here (T-03-08, T-03-09) and audited by /gsd-secure-phase, and is not minted as a prohibition.
- The synthetic-only guard in `RepoHygieneTests` allows a local `clone` and `file://` addresses but flags a string literal that starts with `fetch`, `pull`, `push`, `remote`, `ls-remote` or `submodule` right after `(` or `[`, and any `git@` or `ssh://` text. The helpers clone through a `file://` URI of the sandbox only.
